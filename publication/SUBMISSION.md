# Kane CLI Online Hackathon submission draft

## About the project

FixProof helps developers and QA engineers check whether a proposed fix resolves the reported bug without breaking nearby behavior. The developer supplies baseline and candidate URLs, a written expectation, and controls. Built with Codex, the workflow runs Kane CLI on both builds and records browser observations, build fingerprints, and evidence status. Its repair-brief exporter gives a coding agent the actual failure, selected source references, and an exact command to rerun the same case and controls.

The latest demonstration uses a synthetic cart and one deliberately flawed candidate edit. The reload check passes at 2 items and $48.00, but the immediate-update control catches a regression: the baseline shows 2 items and $48.00 while the candidate still shows 1 item and $24.00. FixProof reports the regression and exits `1`. Passing the reported bug's check alone is insufficient.

The flawed edit was constructed for this demonstration, not generated by Meta. Codex restored the exact previously reviewed source. A fresh Kane comparison then exited `0`: the candidate showed 2 items and $48.00 both immediately after the increase and after reload, using the unchanged case and controls. An earlier retained example separately records an actual Meta patch proposal, its application by Codex, and unchanged Kane verification. This new demonstration makes no additional Meta or Baseten requests and adds no product features.

These results cover the recorded synthetic-cart behavior. FixProof does not apply automatic code edits, and missing evidence stays incomplete. The local preview and sanitized reports provide a fallback without a live Kane account; repeating browser runs requires Chrome and a Kane account with credits. Raw evidence packs remain private.
